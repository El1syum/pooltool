# Стол и окружение: подготовка, библиотека и публикация

В веб-версии добавлена **мастерская моделей**, работающая с настоящим
Three.js-рендерером и GLTFLoader. Готовых художественных моделей в этой поставке
нет: до загрузки моделей используются прежние процедурные стол и пол. Тестовая
GLB-геометрия существует только в тестах и не подменяет собой готовый игровой арт.

## Общая библиотека

Для обычного игрока есть отдельный экран **Настройки → Оформление** с настоящим
3D-предпросмотром. Стол и окружение выбираются независимо: общий вариант сервера,
базовое процедурное оформление или включённая модель из каталога. «Применить»
сохраняет только ID/режимы выбора в этом браузере для текущего игрового профиля;
выбор не меняет оформление соперника и не публикует общую сцену. «Отмена» не
изменяет текущий выбор. Недоступный каталог не стирает сохранённые ID; удалённая
или отключённая модель возвращается к общему варианту после подтверждённого
обновления каталога. Ошибка загрузки GLB оставляет рабочую процедурную геометрию.

Существующая мастерская остаётся отдельным инструментом администратора. Личные
предпочтения не подставляются в её глобальный черновик и не становятся общей
сценой случайно.

Библиотека хранится на сервере, а не только в браузере администратора. Игрокам
доступны список включённых моделей, выбранная сцена и публичные GLB-файлы.
Загрузка, редактирование, отключение и публикация требуют отдельного входа
администратора; авторизация не связана с игровым гостевым профилем. Изменения
передаются через защищённые административной сессией и CSRF-проверкой операции.
Обычный посетитель не может загрузить файл или опубликовать сцену.

Отключённые модели видны только администратору. Кнопка «Восстановить» включает
файл обратно в библиотеке, но не выбирает его и не публикует сцену автоматически.
В локальной Vite-разработке `/models/library` проксируется на тот же API-сервер
`127.0.0.1:8790`, что и `/api`; штатные `/models/balls` остаются статическими файлами.

Текущий тестовый сервер работает по HTTP: пароль и сессионные данные не
защищены транспортным шифрованием. Для публичного production-развёртывания нужен
HTTPS; это не скрывается и не заменяется утверждением, что один пароль защищает
незашифрованный трафик.

В сцене выбираются независимо:

- **стол** — декоративная геометрия корпуса, сукна, бортов, ножек;
- **окружение** — стены, пол, потолок и прочее статичное оформление комнаты.

Серверная публикация выбирает ID обеих моделей и атомарно сохраняет их
трансформации/материалы. Новые игровые сцены получают опубликованный выбор.
Имеющиеся HTTP-ресурсы GLB остаются в рамках того же сервера; библиотека не
позволяет клиенту подставлять произвольные внешние URL.

## Практический процесс

1. Откройте мастерскую и войдите как администратор.
2. Выберите тип «Стол» или «Окружение», затем импортируйте самостоятельный `.glb`.
   На этом шаге файл сохраняется в локальный черновик и показывается в
   предпросмотре. Автоматической отправки на сервер при выборе файла нет.
3. Совместите модель с физической калибровочной сеткой: ПКМ вращает камеру,
   колесо меняет масштаб, кнопки выбирают общий вид и вид сверху.
4. Настройте положение в метрах, углы XYZ в градусах и масштаб по каждой оси.
   При необходимости временно оставьте стандартную геометрию для сравнения.
5. Выберите все материалы или конкретное имя материала; задайте оттенок,
   шероховатость и металличность. Оттенок умножается на исходную PBR-текстуру.
   «Сбросить материал» возвращает исходные значения GLB, а не усреднённый материал.
   Ненужные именованные узлы можно скрыть через список с поиском.
6. «Сохранить модель в библиотеку» загружает/обновляет одну модель. «Опубликовать
   общую сцену» сохраняет выбранные стол и окружение с их настройками для игры.
   До явного сохранения/публикации локальный предпросмотр не меняет общую сцену.
7. Откройте обычную игру и проверьте совпадение сукна, шаров и физических луз.
   Ошибка загрузки не блокирует матч: возвращается стандартная геометрия.

Локальный черновик можно сохранить и восстановить в том же браузере через
IndexedDB. JSON конфигурации экспортируется отдельно; исходный GLB также можно
скачать. JSON с `source.kind = local` не содержит сам файл и не является
переносимой публикацией: на другом устройстве нужны исходный GLB и повторный
импорт либо URL модели общей библиотеки.

## Соглашение о координатах

Рендер использует метры и glTF-оси: **X поперёк стола, Y вверх, Z вдоль стола**.
Начало координат модели стола должно находиться в центре игровой поверхности.
Сама поверхность в исходной модели должна быть на локальной высоте Y=0;
ножки/корпус располагаются ниже. При показе в матче рендерер добавляет реальную
высоту сукна из серверного snapshot (`renderHeight`/`height`).

Для текущего реального 8-ball Pooltool: ширина поля 0,9906 м, длина 1,9812 м,
высота сукна 0,708 м. Края сукна относительно центра: X=±0,4953 и Z=±0,9906.
Ранее указанные 1,27×2,54 м относились к ошибочному локальному предпросмотру,
а не к активному серверному столу. Мастерская теперь запрашивает
`/api/assets/table-reference`: калибровочный snapshot создаёт тот же движок,
который ведёт реальные партии. При недоступном сервере явно указан локальный
эталон. В запущенном матче всегда используются размеры из его snapshot.
Окружение начинается на полу, Y=0; его трансформация не привязана к высоте сукна.
Золотой контур и цветные маркеры в предпросмотре помогают вручную совместить
модель. Проверяйте внутренний размер сукна, а не наружный габарит корпуса.

Это только визуальная калибровка. Физические размеры поля, координаты/радиусы луз,
положения шаров, ограничения установки битка и расчёт столкновений **не меняются
загруженной моделью**. Декоративные меши не перехватывают выбор шаров и луз.
Если заменить стол на иной физический тип/размер, потребуется отдельное изменение
серверного стола, а не только масштабирование картинки.

## Требования к GLB

- glTF 2.0, бинарный самостоятельный `.glb`, максимум 50 МБ.
- Текстуры и буферы встроены в GLB (bufferView или data URI). Внешние URI,
  относительные сторонние файлы, сетевые ссылки и самостоятельные `.gltf`
  отклоняются **до** вызова загрузчика.
- Обязательные Draco, Meshopt и KTX2-декодеры в этом импортере не настроены;
  пересохраните такой файл без обязательного сжатия этими расширениями.
- До 3000 узлов и 1 млн отображаемых вершин с учётом экземпляров. Текстуры
  максимум 8192×8192; для мобильного браузера желательно существенно меньше.
- Экспортируйте осмысленные имена материалов и узлов: они используются для
  индивидуального редактирования (до 160 символов). Совпадающие имена материалов получают общий
  override. Анимации автоматически не проигрываются; это подготовка статичного
  оформления стола/комнаты.

## Код и интеграция

- `online/client/src/models/types.ts` — конфигурация и интерфейс адаптера библиотеки.
- `validation.ts` — проверка GLB/JSON/URL; `store.ts` — локальные исходники/черновик.
- `VisualAssetManager.ts` — ленивый GLTFLoader, трансформации, исходные материалы,
  сброс, отмена устаревшей загрузки, освобождение геометрии/текстур.
- `libraryProfile.ts` — преобразование серверных ID/конфигураций в рендер-профиль.
- `components/ModelWorkshop.vue` — инструмент подготовки с калибровочным
  предпросмотром; административная авторизация остаётся в адаптере приложения.
- `GameScene.setVisualAssets(profile)` — замена оформления без пересоздания canvas.
  `getVisualAssetReport()` возвращает сведения/ошибки по двум ролям;
  `setCalibrationOverlay(true)` включает рабочий контур только в мастерской.

Для статичной подготовки без серверной библиотеки GLB можно разместить под
`online/client/public/models/custom/` и использовать JSON `VisualAssetProfile`
с `source: {kind: "url", url: "/models/custom/name.glb"}`. Это необязательный
технический вариант для локального прототипа; основной пользовательский процесс
текущего проекта — общая серверная библиотека с административной публикацией.

## Проверка

Из `online/client`:

```powershell
node --test --experimental-strip-types src/models/validation.test.mjs
$env:BROWSER = 'chromium' # затем повторить с webkit
node tests/model-workshop.mjs
npm run build
```

Нужен Playwright (`PLAYWRIGHT_MODULE` может указывать на общий установленный
модуль). Браузерный тест поднимает и закрывает Vite на 4316 и генерирует собственный
минимальный GLB-треугольник. Проверены настоящий GLTFLoader/рендер, сохранение
файла после перезагрузки IndexedDB, трансформации и сброс материала, однократное
освобождение геометрии, отмена устаревшей загрузки, запрет внешних URI,
публикация через явно обозначенный тестовый адаптер, read-only режим и узкий
экран. Проверки серверных сессий, CSRF, конкурентной публикации и хранения файлов
находятся отдельно в backend-тестах; тестовый адаптер не выдаётся за сервер.
