# VK Play: подготовленный вход для веб-версии

Публикация игры на VK Play и подключение настоящих ключей пока отложены.
Обычный тестовый URL продолжает работать через существующий гостевой вход.
Значение `VKPLAY_ENABLED` по умолчанию выключено; GMRID и секрет не зашиты в
клиентскую сборку и не нужны для запуска тестовой игры.

## Два независимых режима

- Обычный URL `/`: прежний гостевой профиль и его `pooltool.token` сохраняются.
- Будущий iframe URL `/?platform=vkplay`: отдельный вход через VK Play. Наличие
  сохранённого гостевого токена не позволяет обойти платформенную проверку.
  Если режим выключен, ключей нет или проверка завершилась ошибкой, показывается
  ошибка/повтор входа — автоматического перехода в гостя нет.

Маркер `platform=vkplay` — только выбор режима интерфейса, не доказательство
личности. Сам `uid`, referrer или результат SDK не дают доступ к профилю.

## Схема входа

1. Клиент запрашивает безопасную публичную конфигурацию `/api/auth/config`.
2. Только для включённого и настроенного режима подключается официальный SDK
   `https://vkplay.ru/app/[GMRID]/static/mailru.core.js` и выполняется `iframeApi`.
3. `getLoginStatus()` определяет следующее действие: `0` — вход через
   `authUser()` по нажатию пользователя; `1` — регистрация в игре через
   `registerUser()` с последующим `reloadWindow()`; `2/3` — получение билета.
4. `getAuthToken()` возвращает `uid` и одноразовый `hash`. Это не `hash` из
   `userInfo()`. Клиент передаёт билет POST-запросом нашему серверу, не в URL.
5. Сервер проверяет конфигурацию, входные поля и переданные подписанные параметры
   запуска, затем один раз обращается к фиксированному HTTPS endpoint GAS:
   `https://vkplay.ru/app/[GMRID]/gas`. В подписи учитывается `appid=GMRID`.
6. Только ответ GAS `status=ok` разрешает найти/создать наш внутренний профиль и
   выдать собственную игровую сессию. Дальше работают прежние HTTP Bearer и WS.

Платформенный режим получает свежий билет при каждом запуске. Он не использует
сохранённый гостевой токен и не заменяет его. Токен платформенной игровой сессии
используется в памяти текущей страницы; OTP, секрет и ответ с токеном не должны
попадать в localStorage, URL, телеметрию или диагностические сообщения.

Повтор одного POST обмена после потери ответа использует тот же requestId и
короткий ограниченный серверный кэш. Сам GAS повторно с тем же билетом не
вызывается. Если результат GAS неоднозначен, билет уже использован или сервер
перезапущен, нужно получить новый билет через повтор входа, а не повторять GAS.
Это не обещание восстановления одноразового билета после перезапуска сервера.

## Профили и совместимость

Внешняя идентичность хранится как `(provider, app_id, external_id)`, для этого
добавлена отдельная таблица `external_identities`. Номер VK Play UID не считается
номером пользователя ВКонтакте. Разные GMRID и провайдеры не смешиваются.

Повторные входы в один VK Play аккаунт/проект находят тот же внутренний профиль,
сохраняя имя, Elo, настройки и историю. Гостевой прогресс автоматически не
переносится и не объединяется по имени или почте: такое связывание потребовало бы
отдельного подтверждённого сценария. Существующий `/api/auth/vk` остаётся
отдельной заготовкой VK Mini Apps. Административный вход моделей не изменён.

## Позднее подключение

На сервере, вне Git и клиентской сборки, потребуется настроить:

```dotenv
VKPLAY_ENABLED=true
VKPLAY_GMRID=<числовой ID проекта>
VKPLAY_SECRET=<секрет API из кабинета VK Play>
```

Это пример полей, не файл с действительными ключами. До получения реквизитов
оставить режим выключенным. Одна только запись GMRID/секрета без включения
переключателя не должна включать платформенный вход.

Перед реальной публикацией:

1. Настроить HTTPS-адрес игры и WSS для её WebSocket.
2. Указать iframe URL с `?platform=vkplay` в кабинете проекта.
3. Подключить реквизиты на сервере и перезапустить сервис.
4. Проверить фактические callbacks SDK и GAS настоящими тестовыми аккаунтами:
   первый вход, регистрацию, повторный вход, выход/смену платформенного аккаунта,
   отказы и восстановление соединения. Без действительного проекта это не
   считается проверенным на живой платформе.
5. Проверить получение реального IPv4 клиента за доверенным reverse proxy.
   GAS документирует IPv4: используется ASGI `request.client.host`, а не
   произвольный `X-Forwarded-For` из пользовательского запроса. IPv4-mapped IPv6
   можно нормализовать, но чистый IPv6 нельзя подменять фиктивным адресом.
6. Отдельно согласовать будущую доступность гостевого API в production. В этой
   подготовке гостевой вход специально сохранён для тестовой версии.

## Проверка без настоящих реквизитов

Backend-тесты подменяют только внешний GAS HTTP-транспорт: проверяют подписи,
ошибки, одноразовость, повтор собственного обмена, изоляцию идентичностей и
сохранность старой БД. Они не вызывают настоящую платформу и не заменяют
приёмку с реальными ключами.

Клиентские тесты SDK используют явно обозначенный тестовый API и проверяют
состояния/ошибки и отсутствие гостевого fallback. Сквозной
`tests/vkplay-disabled-integration.mjs` использует настоящий App/API в обоих
браузерах с выключенным режимом: существующий гость сохраняется, маркер платформы
не запускает SDK/GAS и не авторизует гостя, возвращение на обычный URL
восстанавливает прежний гостевой профиль.
