# Игровой интерфейс Pooltool

## Источники и границы

Запрос от 2 ноября 2026 года: начать перенос игрового интерфейса веб-версии по
[Figma](https://www.figma.com/design/qLURhvhuM4AZ0xibHYelU8/?node-id=73-73) и PDF
«Интерфейсное решение PoolTool». Основной экран — `73:73`, состояния прицеливания
и выбора силы — `73:172`, `73:294`, `73:327` в разделе «Дизайн\База».

Комната, художественные модели стола, кия и шаров будут предоставлены позже.
Вместо фонового скриншота используется настоящая интерактивная Three.js-сцена.
Общий вид изображения поэтому пока отличается от иллюстрации в макете.
Начиная с обновления 3 ноября главное меню, поиск, лобби, профиль и настройки
тоже перенесены на новый макет; ниже сохранено описание этапов подготовки удара.

Актуальный источник:
[Figma от 3 ноября](https://www.figma.com/design/YPQR5qd4bL3LUjSRBzTuQH/?node-id=0-1).
Меню — раздел `94:73`, игра — `105:4604`. Фон меню — исходное изображение из
Figma, преобразованное в WebP (1264×848, около 68 КБ). Это не снимок экрана.
В игре по-прежнему используется настоящий 3D-стол.

Дополнительные панели силы, наклона и контакта показываются при удержании Ctrl
по умолчанию. Клавиша переназначается в «Настройки → Управление → Дополнительные
приборы» и сохраняется в профиле. Обе стороны клавиш-модификаторов работают.
Потеря фокуса и отпускание клавиши скрывают карточки; на сенсорном устройстве
есть кнопка «Помощь». Основные шкалы силы в процентах и м/с видны на этапе силы
без удержания Ctrl. Они используют оригинальный актуальный SVG Figma с живой
заливкой, а не статичные значения из примера. Shift + колесо меняет наклон кия.
В рейтинговой партии линия прицеливания принудительно выключена и настройка
заблокирована; личное предпочтение для обычной игры при этом сохраняется.

Общая библиотека моделей открывается из настроек. Подготовка, публикация и
ограничения описаны в [MODEL_ASSET_PIPELINE.md](MODEL_ASSET_PIPELINE.md).

Тестовая версия: http://82.47.143.103:8790. Адрес проверен 2 ноября 2026 года;
при обновлении используется актуальный SSH-хост `el1s`, а не старый сохранённый IP.

## Реализованные элементы

- Полноэкранная игровая сцена с отдельным HUD, без прежней постоянной боковой
  колонки. Открытие панелей не пересоздаёт canvas и не прерывает траекторию.
- Карточки игроков, их инициалы, группы, забитые шары и счёт из семи. До назначения
  групп отображается открытый стол, а не ошибочные «14 личных шаров».
- Подсветка текущего игрока, оставшееся время хода и общее время матча.
- Настройки, звук, подтверждение ухода/сдачи, код комнаты и краткие правила.
- SVG-прицел и два индикатора силы по форме Figma: проценты и м/с. Их заливка
  динамическая; стандартные возможности выбора шара и лузы сохранены.
- Доступная панель «Параметры удара» как альтернатива жестам, для клавиатуры,
  сенсорного управления и точной настройки чисел.

## Подготовка удара

1. По умолчанию свой ход начинается с вида из-за кия. Свободное движение мыши
   выбирает направление. Первый клик ЛКМ фиксирует его. Попадать
   по битку или сукну не требуется: фон вокруг стола тоже подтверждает этап.
   На сенсорном экране касание сукна задаёт направление; касание фона фиксирует
   уже выбранное направление.
2. В режиме прицеливания направление уже зафиксировано. Прицел на битке
   задаёт только точку контакта кия; ЛКМ по свободному месту сцены подтверждает её
   и переводит к силе. Нажатие подтверждения не начинает зарядку: для неё нужно
   новое зажатие ЛКМ. Клики по прицельным шарам/лузам сохраняют выбор заказа.
3. В режиме силы направление и точка контакта зафиксированы. Тянуть вниз —
   увеличивать силу. Оба треугольника показывают одну скорость `V0`: слева
   проценты от 8 м/с, справа м/с. Отпускание ЛКМ после движения вниз хотя бы
   на 8 CSS px отправляет обычную серверную команду удара. Движение вбок
   не меняет скрытый наклон и само по себе не выполняет удар.
4. ПКМ возвращает на предыдущий этап. Простой клик или дрожание указателя
   не должны случайно выполнить удар. Перестановка битка имеет приоритет
   над подготовительными жестами.

Сохраняются переназначенные клавиши и кнопки мыши; явная кнопка удара и горячая
клавиша доступны как альтернативный способ. При открытом меню, правилах или
настройках ввод в сцену заблокирован. Наблюдатель не может выполнить удар.

Проценты силы — представление скорости `V0`, а не отдельный серверный параметр.
Сила ограничена 8 м/с, смещение точки контакта в HUD — диском 0,8. Наклон кия
до 60° остаётся отдельной настройкой в расширенной панели; правый индикатор
по уточнению пользователя показывает скорость, а не угол из примера макета.
Подсказка вида сверху показывает реальную назначенную клавишу, а не статическую
букву F: прежнее назначение F для винта не затирается без согласования.

## Ассеты и проверка

Оригинальные SVG и их Figma-слои перечислены в `public/ui/figma-match/ASSETS.md`.
В коде нет временных Figma URL, скриншот не заменяет игровое поле. Шрифты Inter
и Lora размещены локально вместе с OFL-лицензиями.

Проверки запускаются из `online/client`:

```powershell
npm run build
node --test tests/hud-ssr.test.mjs
node --test --experimental-strip-types src/game/playback.test.mjs src/game/shotWorkflow.test.mjs
node tests/match-hud.mjs
node tests/browser-smoke.mjs
node tests/power-gauges.mjs
```

Для браузерных сценариев нужны работающий сервер с настоящей физикой и
Playwright; параметры окружения описаны в `tests/README.md`. Проверять нужно
не только размеры HUD, но и реальный удар, восстановление, права зрителя,
сохранность canvas, обязательную постановку битка, шрифты и геометрию SVG.
WebKit-проверка не заменяет сертификацию нативного Safari на Apple-устройстве.

Актуальный контур индикаторов — нетронутый SVG-экспорт `105:4605` из нового
файла, `public/ui/figma-assist/power-gauge.svg` (149.714×82.5888). Динамическая
заливка использует точную исходную геометрию Vector 3 внутри компонента с
локальными gradient/clip ID для совместимости Safari; внешний SVG `use` для
основных треугольников больше не требуется. Это не скриншот и не перерисовка.
Относительно контейнера прицела 316×316 позиции: слева (-77,181), справа
(242.786,45); левый индикатор повёрнут на 180°. Это расположение плавающих
групп `105:4617`/`105:4626` из Figma, а не их неполный экспорт внутри фрейма.
Пиксельные тесты подключают обе актуальные таблицы стилей, проверяют рост
заливки для 0/25/50/100%, одинаковую силу и адаптивные границы.

Повторная сверка всех экранов, исправления и оставшиеся ограничения описаны
в [FIGMA_AUDIT_20261105.md](FIGMA_AUDIT_20261105.md).

Проверка опубликованной сборки `index-e5-XYRcV.js` прошла в Chromium: реальный
удар выполнен подтверждением точки контакта, оттяжкой и отпусканием мыши.
Сервер получил выбранные 3 м/с и неизменное направление 90°; итоговое положение
совпало у двух игроков и зрителя. В локальных Chromium/WebKit также прошли
проверки HUD, пиксельной заливки и управление сценой; pure/SSR — 23 теста.
