# Возврат управления после потери фокуса

Обновление от 6 ноября 2026 года. Это пауза локального ввода, не сетевая пауза:
таймер хода и серверная игра продолжаются.

## Правило пользовательского намерения

| Событие | Ввод и параметры удара | Захват курсора |
| --- | --- | --- |
| Обычное прицеливание | Направление → контакт → сила по действующему управлению | Разрешён только активной сцене своего хода |
| Blur, скрытая вкладка, неожиданная потеря захвата | Жест отменяется; `phi/a/b/theta/V0` и этап сохраняются | Собственный захват отпускается, право автоповтора отзывается |
| Возврат фокуса, входящий снимок, новый ход | Ввод остаётся замороженным, HUD не меняет контакт от hover | Захвата нет |
| ЛКМ по сцене или «Продолжить игру» | Только явное возобновление; этот клик не подтверждает этап и не стреляет | Новый запрос лишь в переднем видимом окне и подходящем режиме |
| Захват запрещён/не поддержан | После явного возобновления остаётся управление у края экрана | Курсор не прячется обходными способами |

Возобновляющий pointerdown/up поглощается до переназначений кнопок, raycast,
заказа шара/лузы, постановки битка и оттяжки. Во время удержания такого клика
движение не меняет удар. Pointercancel снова ставит ввод на паузу. Touch
возобновляется на pointerup, когда браузер предоставляет пользовательскую
активацию; отдельное следующее касание выполняет обычное подтверждение.

## Границы ответственности

- `createGameScene.ts` владеет захватом, жестами и suspended-состоянием.
- `onInputSuspendedChange` блокирует интерактивный HUD, не меняя серверное
  разрешение хода. Это предотвращает тупик, при котором сцене нельзя возобновиться.
- `isInputSuspended()` синхронно проверяет передний план и фактического владельца
  мыши перед HUD-командой. Нельзя полагаться только на отложенный DOM callback:
  `pointerLockElement` может измениться раньше `pointerlockchange`.
- Входящие события сети и создание нового собственного хода не снимают gate.
  App сохраняет его также при пересоздании сцены и смене идентичности.
- Настройки, правила и меню доступны. Ctrl-приборы — временный интерфейсный
  unlock, он не приравнивается к уходу в другое приложение.
- Запросы захвата имеют владельца/поколение. Старое завершение не освобождает
  более новый валидный захват. Поздний grant в неактивную/уничтоженную сцену
  отклоняется; `exitPointerLock()` применяется только к собственному canvas.
- Modern Promise errors принадлежат своему запросу. Глобальная ошибка legacy
  void API не должна отменять чужое намерение. Pending-защита ограничена по времени.
- Запоздавшее глобальное NONE после штатного unlock не считается потерей нового
  Promise-запроса. Успешный request-owned Promise отдельно проверяет grant→loss,
  даже если оба DOM-уведомления ещё стоят в очереди.

Браузерная спецификация допускает повторный захват после собственного
`exitPointerLock()` без нового действия. Поэтому одного разрешения браузера и
`hasFocus()` недостаточно: приложение отдельно помнит уход пользователя.
Источники: [W3C Pointer Lock](https://www.w3.org/TR/pointerlock/) и
[HTML user activation](https://html.spec.whatwg.org/multipage/interaction.html#activation-triggering-input-event).

## Проверки

- `tests/cursor-resume.mjs`: настоящий Three.js, native Pointer Lock в Chromium,
  отказ/отсутствие API в обоих браузерах, сохранение всех параметров и этапов,
  прерванная оттяжка, Mouse0, touch/cancel, фоновое создание/новый ход, поздние
  grant/resolve и старый запрос A после нового захвата B.
- `tests/cursor-resume-app.mjs`: настоящий App/API, замороженный контактный HUD,
  явная кнопка продолжения, безопасный возврат в трёх этапах и пересоздание сцены.
- `tests/match-hud.mjs`: настоящий трёхклиентский физический матч с явным
  возобновлением после проверочного blur; без скриптового обхода защиты.

Headless-браузеры не воспроизводят переключение окон ОС достоверно: например,
`bringToFront()` второй вкладки может не изменить `hasFocus()` первой.
Потеря фокуса там моделируется явно помеченными blur/visibility/API fixtures;
native захват проверяется отдельно. Полная сертификация Alt+Tab конкретной ОС
и Safari на физическом устройстве не заявляется.
